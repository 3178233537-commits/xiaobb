# 实验报告：用户登录模块设计与实现

> 项目：星选 Nova 高端商城（纯前端 SPA）
> 模块：用户登录 / 注册 / 第三方快捷登录 / 会话管理
> 日期：2026-10-17 ｜ 源码：[js/auth.js](../js/auth.js)、[js/app.js](../js/app.js)、[index.html](../index.html)

## 一、实验目的

1. 在无后端条件下，设计并实现符合现代 Web 安全规范的完整登录流程：账号密码登录、注册、第三方快捷登录。
2. 实现表单实时校验、错误反馈、防暴力破解锁定、登录状态持久化。
3. 登录流程与购物业务联动（未登录结算拦截 → 登录后自动回到结算）。
4. 通过浏览器自动化完成全流程测试验证。

## 二、总体设计

### 2.1 架构分层

```
┌─────────────────────────────────────────────────┐
│ LoginUI   界面逻辑：校验、强度条、抖动反馈、提交    │
├─────────────────────────────────────────────────┤
│ OAuth     第三方授权弹窗（模拟授权码流程）          │
├─────────────────────────────────────────────────┤
│ Auth      认证核心：哈希、会话、用户库、失败锁定    │
├─────────────────────────────────────────────────┤
│ 存储层    localStorage / sessionStorage          │
└─────────────────────────────────────────────────┘
```

### 2.2 登录状态机

```
未登录 ──提交表单──▶ 校验中 ──成功──▶ 已登录（写会话→更新UI→回首页/续结算）
   │                   │
   │                   └─失败──▶ 错误提示 + 卡片抖动（累计 5 次 → 锁定 30s）
   │
   └──第三方按钮──▶ 授权弹窗 ──同意──▶ 已登录（同上）
```

### 2.3 存储模型

| 键 | 位置 | 内容 |
|---|---|---|
| `nova_users` | localStorage | 用户库：`{账号: {salt, hash, nickname, provider, createdAt}}` |
| `nova_session` | localStorage（记住我）/ sessionStorage（不记住） | `{account, nickname, provider, token, loginAt, remember}` |
| `nova_lock` | localStorage | 失败计数 `{n, until}` |

## 三、关键实现与重要代码

### 3.1 密码安全：SHA-256 + 随机盐哈希（绝不明文落盘）

注册时生成 8 字节随机盐，存储 `hash = SHA256(salt + password)`；登录时同法比对。优先使用 Web Crypto API（需安全上下文，故本项目要求经 `http://localhost` 访问），并保留降级哈希保证可用性。

```js
const toHex = buf => [...new Uint8Array(buf)].map(b => b.toString(16).padStart(2, '0')).join('');
const rand = n => toHex(crypto.getRandomValues(new Uint8Array(n)));

async function hash(str) {
  if (crypto && crypto.subtle) {
    try {
      return toHex(await crypto.subtle.digest('SHA-256', new TextEncoder().encode(str)));
    } catch (e) { /* 回退 */ }
  }
  let h = 5381;
  for (const c of str) h = (h * 33 ^ c.charCodeAt(0)) >>> 0;
  return 'x' + h.toString(16);
}

async function register({ account, password, nickname }) {
  const a = normAcc(account);
  const users = getUsers();
  if (users[a]) return { ok: false, msg: '该账号已注册，请直接登录' };
  const salt = rand(8);                                   // ← 每用户独立随机盐
  users[a] = { salt, hash: await hash(salt + password),   // ← 只存盐+哈希
               nickname: nickname || maskName(a), provider: 'local', createdAt: Date.now() };
  saveUsers(users);
  return startSession(users[a], a, true);
}
```

> 注：真实生产环境应使用 bcrypt/argon2 等慢哈希 + 服务端存储；本实验以前端可运行的 SHA-256+盐演示「不可逆存储 + 盐防彩虹表」的核心思想。

### 3.2 输入校验：账号识别 + 密码策略

```js
const isPhone = v => /^1[3-9]\d{9}$/.test(v);
const isEmail = v => /^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$/.test(v);
const accType = v => isPhone(v) ? 'phone' : isEmail(v) ? 'email' : null;

function checkPwd(p) {
  if (!p) return '请输入密码';
  if (p.length < 8 || p.length > 20) return '密码长度需为 8-20 位';
  if (!/[A-Za-z]/.test(p) || !/\d/.test(p)) return '密码需同时包含字母和数字';
  return null;
}
```

### 3.3 表单实时校验与提交（LoginUI）

`input` 事件即时校验（错误随输入消失）；提交时用**位与 `&`** 强制四个校验全部执行，确保所有错误一次性展示；失败时卡片播放 `shake` 抖动动画并显示红色错误条。

```js
async function submit(e) {
  e.preventDefault();
  if (Auth.lockRemain() > 0) { startLockCountdown(); return; }

  const ok = vAccount() & vPwd() & vPwd2() & vAgree();  // 位与：全部执行，收集全部错误
  if (!ok) { shake(); return; }

  const btn = $('submitBtn');
  btn.disabled = true;
  btn.innerHTML = '<span class="spinner"></span>' + (mode === 'register' ? '正在创建…' : '登录中…');

  await new Promise(r => setTimeout(r, 600));            // 模拟网络时延，反馈更真实
  const res = mode === 'register' ? await Auth.register(payload) : await Auth.login(payload);

  if (res.ok) {
    Auth.resetFail();
    window.App && App.onAuthSuccess(res.user);           // 导航栏切换为头像
    if (Shop.consumePendingCheckout && Shop.consumePendingCheckout()) {
      window.App && App.goHome();
      Shop.openCheckout();                               // 登录前点了结算 → 自动回到结算
      window.App && App.route();                         // 兜底：保证视图与路由一致
    } else {
      window.App && App.goHome();
    }
    Shop.toast(`欢迎回来，${res.user.nickname}`, 'success');
  } else {
    if (mode === 'login') Auth.onFail();                 // 失败计数 → 触发锁定
    $('formErr').textContent = res.msg;
    $('formErr').hidden = false;
    shake();
    btn.disabled = false;
    btn.textContent = mode === 'register' ? '注册并登录' : '登录';
  }
}
```

### 3.4 会话签发与持久化（记住我）

```js
function startSession(u, account, remember) {
  const ses = { account, nickname: u.nickname || maskName(account, u.provider),
                provider: u.provider || 'local', token: rand(32),  // 256 位随机 Token
                loginAt: Date.now(), remember: !!remember };
  (remember ? localStorage : sessionStorage).setItem(K_SES, JSON.stringify(ses));
  return { ok: true, user: ses };
}

function current() {   // 会话读取：先短期（sessionStorage）后长期（localStorage）
  try {
    return JSON.parse(sessionStorage.getItem(K_SES)) || JSON.parse(localStorage.getItem(K_SES));
  } catch { return null; }
}
```

**设计要点**：昵称展示做隐私脱敏（手机号 `138****5678`、邮箱取前缀），Token 仅用于会话标识，不存储任何敏感信息。

### 3.5 防暴力破解：失败锁定

```js
function onFail() {
  const l = lockInfo();
  l.n += 1;
  if (l.n >= 5) { l.until = Date.now() + 30000; l.n = 0; }   // 5 次失败锁 30 秒
  localStorage.setItem(K_LOCK, JSON.stringify(l));
  return l;
}
const lockRemain = () => Math.max(0, Math.ceil((lockInfo().until - Date.now()) / 1000));
```

锁定期间提交按钮禁用并倒计时显示「尝试过于频繁，Ns 后再试」，登录成功后 `resetFail()` 清零。

### 3.6 第三方快捷登录（模拟 OAuth 授权码流程）

真实 OAuth 需服务端配合，本实验完整复刻其**交互语义**：用户点击 → 弹出授权确认卡（展示申请方与权限范围）→ 用户同意 → 以该提供商身份签发会话；取消则无任何状态变更。

```js
function social(provider) {
  OAuth.open(provider, async () => {                        // 用户在授权卡点「同意」
    const res = await Auth.thirdLogin(provider);
    if (res.ok) {
      window.App && App.onAuthSuccess(res.user);
      if (Shop.consumePendingCheckout && Shop.consumePendingCheckout()) {
        window.App && App.goHome();
        Shop.openCheckout();
        window.App && App.route();
      } else {
        window.App && App.goHome();
      }
      Shop.toast(`已通过${{wechat:'微信',apple:'Apple',github:'GitHub'}[provider]}快捷登录`, 'success');
    }
  });
}
```

```js
async function thirdLogin(provider) {
  const a = `${provider}@nova.demo`;                        // 提供商账号命名空间
  const users = getUsers();
  if (!users[a]) {                                          // 首次授权自动建档
    const salt = rand(8);
    users[a] = { salt, hash: await hash(salt + rand(16)),   // 随机口令哈希，不可被密码登录
                 nickname: PROVIDER_NICK[provider] || '访客', provider, createdAt: Date.now() };
    saveUsers(users);
  }
  return startSession(users[a], a, true);
}
```

### 3.8 路由守卫（app.js）

```js
function route() {
  if (location.hash.startsWith('#/login') && Auth.current()) {
    location.hash = '#/home';            // 已登录访问登录页 → 同步重定向
  }
  const isLogin = location.hash.startsWith('#/login');
  $('view-home').hidden = isLogin;
  $('view-login').hidden = !isLogin;
  if (isLogin) LoginUI.open();           // 重置按钮状态、聚焦账号框
}
```

## 五、结论

本实验在纯前端环境下完整实现了登录模块的设计目标：密码经随机盐 + SHA-256 不可逆存储、256 位随机 Token 会话、「记住我」双存储介质持久化、失败 5 次锁定 30 秒的防暴力机制、模拟 OAuth 的第三方授权交互，以及与购物结算流程的无缝联动。10 项自动化用例全部通过，修复了 3 处真实缺陷，验证了状态机与路由守卫设计的正确性。

**局限与改进方向**：前端存储无法替代服务端认证（任何人可读写 localStorage），生产环境应改为：服务端会话/JWT + HttpOnly Cookie、慢哈希（bcrypt/argon2）、验证码与限流、HTTPS 强制传输；第三方登录应接入真实 OAuth 2.0 授权码 + PKCE 流程。
